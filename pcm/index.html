PCM Crossbar Simulator

A crossbar is a grid of phase-change cells. Each word line (a row) carries an input voltage, each bit line (a column) collects current, and a cell sits at every crossing with its stored conductance G.

Input voltages on the word lines produce bit-line currents that already equal the matrix product, Iⱼ = Σᵢ Vᵢ·Gᵢⱼ, so the multiply and the sum both happen inside the array. The array behaves like the PCM one, with two PCM differences you can switch on here: weights are written with the one-directional SET staircase from Step 2, and the stored conductances drift after the write.

This is a generic, textbook model of analog PCM compute-in-memory: a passive crossbar with differential conductance pairs, a quantized DAC and ADC, Gaussian device variation, wire IR drop, a pulse-and-verify write model and power-law drift. It is meant for learning and quick experiments, not as a model of any specific chip.

Negative weights: signed or unsigned, one cell or two? read when you reach negative weights

A PCM cell is a conductance G, and G can never be negative, so a current I = V·G can never be negative either. A weight is the number that scales an input, and weights are often negative as well as positive. Two separate design choices decide how the array copes, and you can set each one with the drop-downs above.

1. Weight sign: are negative weights needed?
Signed keeps them, so the output can go below zero. Unsigned gives up on them: a negative weight is stored as 0. That is fine when every weight is naturally positive (pixel intensities, counts, probabilities), and wrong when it is not.
2. Cells per weight: how is a signed weight stored?
G⁺/G⁻ pair uses two cells: one holds the positive part, one the negative part, and the column pair’s currents are subtracted. G⁺ only uses one cell. To keep negatives anyway it shifts the weight into 0 to 1 and subtracts a shared reference column that stands for zero.

L is the number of conductance levels minus one (set by “Weight levels”) and ΔG = Gmax − Gmin. The fourth combination, unsigned with a pair, is not offered: G⁻ would stay at Gmin and the second cell would buy nothing.

Why not always use the pair? It is the most accurate way to keep negatives, but it doubles the cells, the bit lines and the ADCs. If area or energy is tight, one cell per weight is attractive.
Why does the reference column halve the resolution? One cell has to cover weights from −1 to +1, so the same conductance range is spread over twice the span. Each level now means a change of 2/L in w instead of 1/L.
What does unsigned really cost? Negative weights turn into 0 and the leakage current of every cell piles up in the sum. The error is large when many weights are negative and small when none are.

Try it. (1) Press Randomize with Signed, pair, note y₁, then switch to Unsigned: negative weights turn red and y₁ moves. (2) Press “Make weights positive” and the unsigned result now differs from ideal only by the leakage offset. (3) Set σ = 0 and the ADC to 8 bits, then compare Signed, pair and Signed, G⁺ only: the same ideal answer, but the second is coarser when Weight levels is small. (4) Combine with Binary weighted cells to see the same three layouts at bit level.

Writing the weights into the array

Before any multiply, each weight has to be written as a conductance. The controller first RESETs the array to the amorphous, high-resistance state, then crystallizes each cell a little at a time with SET pulses, reading it back after every pulse and stopping when it is within tolerance of its target. A SET can only raise G, so if a pulse overshoots the cell is RESET and the climb starts again. The conductances this produces are the ones the crossbar uses, and they start to drift as soon as the write ends.

Efficiency versus digital multiply-accumulate

A conventional processor fetches every weight from memory and performs the M×N multiply-adds one batch at a time. The crossbar keeps the weights where they are and finishes all of them in a single read.
