CAN reference

The equations, terms, symbols and settings used across the three CAN steps, in one place. Keep it open next to the simulator, or use it to look something up when a word is new. Everything here describes classical CAN (2.0A and 2.0B) as a teaching model, and the numbers in the worked examples were taken from the simulators themselves.

The path of a sensor reading in one line

Everything in the simulators sits somewhere on this path. The first and last steps are in software. The middle is what the bus hardware does.

  1. software

    Sample

    value

    A sensor node measures, for example 87.3 km/h.

  2. software

    Scale

    raw = round((v − offset) / scale)

    The value becomes an integer in 1 or 2 bytes.

  3. controller

    Frame and CRC

    SOF · ID · DLC · data · CRC

    The controller adds the fields and the 15-bit CRC.

  4. controller

    Stuff

    after 5 equal bits

    An opposite bit is added so receivers keep their clocks.

  5. bus

    Arbitrate

    wired AND

    If others start too, the lowest identifier wins.

  6. bus

    Wires

    V_diff ≈ 0 V or 2 V

    Bits go out as a voltage difference on CAN_H and CAN_L.

  7. controller

    Check and acknowledge

    destuff, CRC, ACK

    Receivers remove stuff bits, check the CRC and send the ACK.

  8. software

    Decode and age

    The dashboard converts back and notes when the frame arrived.

Key equations

Each one has a worked example with the numbers the simulators use (500 kbit/s, an 80% sample point, 150 ns of node delay) and a pointer to where you can see it. Equations 4, 12 and 14 describe this teaching model, not a particular device or the complete standard.

1. The wired AND

bus = b_A AND b_B AND b_C ...
dominant = 0, recessive = 1

The bus is recessive (1) only when no node drives dominant. If any node drives dominant (0), the bus is 0. Every node reads the bus back while it sends, so it can compare what it sent with what is there.

Example. A sends 1, B sends 0, C sends 1: the bus is 0. A and C read 0, so both see a mismatch and know someone else is dominant. B reads 0, which is what it sent.

Used in: Step 1, section 1. Step 2, step 5.

2. Differential levels and the receiver rule

V_diff = V(CAN_H) − V(CAN_L)
recessive: 2.5 V and 2.5 V, V_diff ≈ 0 V
dominant:  3.5 V and 1.5 V, V_diff ≈ 2 V
receiver: V_diff > 0.9 V → dominant
          V_diff < 0.5 V → recessive
          in between → keep the last bit

The receiver looks only at the difference of the two wires, so noise that moves both wires together cancels. The gap between 0.5 V and 0.9 V is margin. A real transceiver also has a common-mode input range of about −2 V to +7 V.

Example. A 3 V spike on both wires turns recessive into 5.5 V / 5.5 V and dominant into 6.5 V / 4.5 V. The difference is still 0 V or 2 V, and both are inside the −2 V to +7 V range, so the bits are read correctly. A single wire against ground with a 2.5 V threshold would read a 0 as a 1.

Used in: Step 1, section 2.

3. Bit time and sample point

T_bit = 1 / bit rate
T_bit = (Sync + Prop + Phase1 + Phase2) time quanta
sample point = (Sync + Prop + Phase1) / total quanta

There is no clock wire. Each node divides the bit into time quanta from its own oscillator and reads the bus once per bit, at the sample point. Typical sample points are 75 to 87.5%.

Example. At 500 kbit/s T_bit = 2 µs. An 80% sample point reads the bus 1.6 µs after the bit starts. If the bit is 10 quanta of 200 ns, that is after the eighth quantum.

Used in: Step 1, section 3. Step 2 and Step 3, bit rate.

4. The longest bus (round-trip rule)

2 × (L × t_prop + t_node) ≤ SP × T_bit
L_max = (SP × T_bit − 2 × t_node) / (2 × t_prop)
t_prop = 5 ns/m

A node checks the bus while it sends, so its bit has to reach the far end and come back before the sample point. A faster bit rate leaves less time, so the bus has to be shorter. The 5 ns/m and the node delay are illustrative.

Example. SP = 80% and t_node = 150 ns. At 500 kbit/s: (1600 − 300) / 10 = 130 m. At 1 Mbit/s: (800 − 300) / 10 = 50 m. At 250 kbit/s 290 m, at 125 kbit/s 610 m. Doubling the rate cuts the length by a little more than half, because t_node does not shrink.

Used in: Step 1, section 3, bus length, sample point and node delay sliders.

5. Frame length in bits (classical CAN)

standard, no stuffing:  8n + 47
extended, no stuffing:  8n + 67
worst-case stuffing:
  standard  8n + 47 + ⌊(34 + 8n − 1) / 4⌋
  extended  8n + 67 + ⌊(54 + 8n − 1) / 4⌋

n is the number of data bytes (0 to 8). The 34 fixed bits of a standard frame are SOF 1, ID 11, RTR 1, IDE 1, r0 1, DLC 4 and the CRC 15. An extended frame has 54. These and the data bits are the ones that get stuffed. The 13 bits of tail (CRC delimiter, ACK slot, ACK delimiter, 7 EOF bits and the 3-bit gap) are not. Worst case adds one stuff bit per 4 bits of the stuffed part.

Example. A standard frame with 8 data bytes is 111 bits with no stuffing and at most 135 with worst-case stuffing, which is 270 µs at 500 kbit/s. An extended frame is 131 and 160 bits. A 2-byte frame is 63 and 75 bits.

Used in: Step 1, section 4 tiles. Step 2, steps 2 and 4. Step 3, Bit stuffing setting.

6. CRC-15

G(x) = x¹⁵ + x¹⁴ + x¹⁰ + x⁸ + x⁷ + x⁴ + x³ + 1   (0x4599)
CRC = remainder of (message bits × x¹⁵) ÷ G(x)
message = SOF to the end of the data field

The sender divides the bits from the start of the frame to the end of the data field by a fixed polynomial and sends the 15-bit remainder. The receiver does the same and compares. The CRC is computed before bit stuffing and does not cover stuff bits. The simulator runs it one bit at a time: shift left, and if the top bit XOR the new bit is 1, XOR in 0x4599.

Example. A standard frame with ID 0x0A0, no RTR, DLC = 2 and data 1A 22 has 35 message bits and CRC = 0x4F31.

Used in: Step 2, step 3.

7. Bit stuffing

after 5 equal bits, insert 1 bit of the opposite value
the stuff bit starts the next run
applies from SOF to the end of the CRC sequence
receiver: a 6th equal bit is a stuff error

A long run of equal bits has no edges for the receivers to synchronise on. After every five equal bits the sender adds the opposite bit, and the receiver removes it. The stuff bit counts toward the next run of five, so a stuff bit can itself cause another one.

Example. Five zeros 00000 go on the wire as 000001. The 63-bit frame in equation 6 gets 2 stuff bits and becomes 65 bits.

Used in: Step 1, section 3. Step 2, step 4. Step 3, Bit stuffing setting.

8. Arbitration

send the identifier MSB first, reading the bus on every bit
if I sent 1 and read 0: I lose, stop, listen
smaller arbitration field wins (0 is dominant)

At the first bit where two arbitration fields differ, the smaller one has a 0 (dominant) and the larger one a 1 (recessive). The 0 overwrites the 1, so the larger one sees a mismatch and drops out. The winner’s bits are never damaged, so arbitration is non-destructive. The arbitration field includes the bits after the identifier: for a standard and an extended frame with the same 11 leading bits, the standard frame wins because its RTR bit is dominant while the extended frame’s SRR bit is recessive.

Example. 0x0A0 = 00010100000 and 0x120 = 00100100000. They first differ at the third bit, 0 against 1, so 0x0A0 (wheel speed) wins and 0x120 (engine speed) waits for the next gap.

Used in: Step 2, step 5. Step 3, identifiers and the priority of the extra traffic.

9. Bus load

U = Σ C_i / T_i
measured load = (time the bus is busy) / (run length)
C_i = (bits in frame i) × T_bit

Each message uses C_i of bus time every T_i. The sum is the share of time the bus is busy. Load is an average: a message can still wait for others at a moment when the average is low.

Example. At 500 kbit/s with worst-case stuffing, the 2-byte frames take 75 × 2 µs = 150 µs and the 1-byte frames 65 × 2 µs = 130 µs. Wheel, steering and engine every 10 ms: 3 × 1.5% = 4.5%. Throttle every 20 ms: 0.65%. Coolant and fuel add 0.04%. The total is 5.2%. At 125 kbit/s every term is 4 times bigger: 20.8%.

Used in: Step 3, load readings, Bit rate setting.

10. Scaling a sensor value into data bytes

raw = round((value − offset) / scale)
value = raw × scale + offset
raw is sent least-significant byte first, in 1 or 2 bytes
signed values use two’s complement

A frame carries integers, not decimals. The sensor value is converted to an integer, so the dashboard can only show values that are a whole number of scale steps from the offset. The largest rounding error is half a step, scale / 2.

Example. Wheel speed (scale 0.01): 87.3 km/h → raw 8730 = 0x221A → bytes 1A 22. Steering (scale 0.1, signed, 2 bytes): −12.5° → raw −125 = 0xFF83 → bytes 83 FF. Throttle (scale 0.4): 33.3% → raw 83 → 33.2%, a rounding error of 0.1. Coolant (offset −40): 90 °C → raw 130 = 0x82.

Used in: Step 3, section 1 (sensor table).

11. Error counters and bus-off

failed send: TEC ← TEC + 8
good send:   TEC ← TEC − 1  (not below 0)
TEC ≥ 128: error-passive
TEC > 255: bus-off, silent until recovery
recovery ≥ 128 × 11 recessive bit times

Every transmit error is worth eight good frames, so a node that fails only occasionally drifts back to zero, and a node that fails often climbs. An error-passive node waits longer before it may send again, and a bus-off node stays off the bus until it has seen the recovery sequence. The standard also has counter rules this teaching model skips.

Example. Break-even is when 8p = 1 − p, so p = 1/9: a node that loses about one frame in nine holds steady, fewer and it recovers, more and it climbs. At 500 kbit/s the minimum recovery is 128 × 11 × 2 µs = 2.8 ms. In the Step 3 simulator with 40% noise (noise seed 7), the run has 28 bus-off events among the sensor nodes.

Used in: Step 2, step 6. Step 3, Noise and Restart after bus-off.

12. Cost of a frame destroyed by noise (teaching model)

wasted time = (k + 6 + 8 + 3) × T_bit
k = position of the damaged bit in the frame (1 to the end of the frame)
the sender then sends the same frame again

When a node detects an error it sends a 6-bit error flag, followed by an 8-bit delimiter and the 3-bit gap, and the frame is sent again. The simulator draws a hit frame as a red block of this length. Frames hit late in the frame cost more.

Example. A hit on bit 40 at 500 kbit/s: (40 + 6 + 8 + 3) × 2 µs = 114 µs wasted before the retry, about as long as a whole 1-byte frame (55 to 65 bits, 110 to 130 µs).

Used in: Step 3, red blocks in the timeline, Noise setting.

13. Worst-case response time (Davis et al.)

C_i = worst-case frame time
B_i = max C_k over messages with lower priority than i
w_i = B_i + Σ over higher priority k of ⌈(w_i + J_k + T_bit) / T_k⌉ × C_k
R_i = J_i + w_i + C_i

A message can be blocked once by a lower-priority frame already on the wire, then delayed by every higher-priority message that is released while it waits. w_i appears on both sides, so the simulator starts at B_i and repeats until it stops changing. R_i is the bound to compare with the period. The bound assumes no noise.

Example. At 500 kbit/s with the six sensors: coolant is blocked at most by the 130 µs fuel frame, then waits for wheel, steering and engine (150 µs each) and throttle (130 µs) once each. w = 130 + 580 = 710 µs and R = 710 + 130 = 840 µs, against a period of 500 ms. Observed in a healthy run: at most 0.11 ms.

Used in: Step 3, calculated worst-case table.

14. When a reading is stale

age = now − (time the last frame for this sensor ended)
stale if age > k × T_sensor
stale share = (time stale) / (run length)

A classical CAN frame has no freshness flag, so the receiver can only look at the clock. The limit is a multiple k of each sensor’s own period, because a slow signal can go longer without an update than a fast one.

Example. With k = 3: wheel speed (10 ms) is stale after 30 ms, coolant (500 ms) after 1.5 s and fuel (1000 ms) after 3 s. With 150% extra traffic at the middle priority at 125 kbit/s, coolant is stale for 34, 31 and 25% of the run at k = 2, 3 and 5.

Used in: Step 3, Stale after setting, tiles and Stale column.

15. Payload efficiency

efficiency = 8n / (bits in the frame, including the gap)

Most of a classical frame is overhead, so even at the best case only a little over half the bit rate carries data.

Example. 8 data bytes: 64 / 111 = 57.7% with no stuffing and 64 / 135 = 47.4% with worst-case stuffing. A 2-byte frame like wheel speed: 16 / 63 = 25.4% and 16 / 75 = 21.3%. A 1-byte frame: 12 to 15%.

Used in: Step 1, section 4.

16. Links without a bus

links = n × (n − 1) / 2

Connecting every pair of n nodes directly needs this many links, but a bus needs only n short stubs onto one pair of wires.

Example. 20 ECUs need up to 190 point-to-point links, or 20 stubs on a bus. The six sensors and the dashboard are 7 nodes: 21 pairs.

Used in: Step 1, section 1.

Glossary

Type to filter the 58 terms by name or by anything in the definition.

Acceptance filter
A setting in a receiving node’s controller that says which identifiers it wants. Nothing on the bus is addressed to a node, so every node hears every frame and keeps the ones its filter lets through.
ACK error
The transmitter reads a recessive ACK slot: no node acknowledged the frame, so it signals an error and sends the frame again.
ACK slot and ACK delimiter
Two bits after the CRC. The transmitter sends the ACK slot recessive, and any receiver that got the frame without detecting an error overwrites it with a dominant bit. The delimiter that follows is always recessive.
Alive counter
A small number in the data bytes that goes up by one with each frame. A receiver that sees it repeat knows the sender is frozen even though frames still arrive. It is an application-level add-on, not part of the CAN frame.
Arbitration
The way nodes decide who sends when several start at once. They send the identifier bit by bit, read the bus, and drop out when they see a dominant bit while sending a recessive one.
Arbitration field
The identifier plus the RTR bit (or the SRR, IDE and RTR bits of an extended frame). Arbitration compares it from the first bit.
Babbling node
A node that sends far more often than it should, for example a faulty ECU or a bug. If its identifier has a high priority it starves every lower-priority message.
Bit error
A transmitting node reads a bus level different from what it sent, outside the arbitration field and the ACK slot. It signals an error.
Bit rate
How many bits the bus carries per second. Classical CAN runs from about 10 kbit/s to 1 Mbit/s. All nodes must use the same rate.
Bit stuffing
After five equal bits the sender inserts one of the opposite value, and the receiver removes it. It guarantees edges for synchronisation. The frame length therefore depends on the data.
Bit time
The duration of one bit, 1 / bit rate. It is split into time quanta and four segments: Sync, Propagation, Phase 1 and Phase 2.
Blocking
A message that has just become ready waits because a lower-priority frame is already on the wire. A frame in progress is never interrupted, so the wait is at most one frame.
Bus load
The share of time the bus is busy sending frames, from 0 to 100%. A bus with a load below 100% can still delay a message, because delay depends on what is on the bus at the moment it becomes ready.
Bus-off
The state of a node whose transmit error counter has passed 255. It stops taking part until it has seen a recovery sequence of 128 times 11 recessive bits, and the software chooses when to try.
CAN (Controller Area Network)
A message-based, multi-master serial bus developed by Bosch in the 1980s for vehicles and standardised as ISO 11898.
CAN FD
A newer version that sends the data part at a faster rate and carries up to 64 bytes per frame. It is compared with classical CAN in Step 1 but is not simulated.
CAN_H and CAN_L
The two wires of the twisted pair. When the bus is recessive both sit near 2.5 V. When it is dominant, one wire rises to about 3.5 V and the other falls to about 1.5 V. The one that goes high is CAN_H (H for high) and the one that goes low is CAN_L (L for low). The receiver reads the difference between them: about 2 V is dominant, about 0 V is recessive.
Common-mode noise
Noise that moves both wires of a pair by the same amount. A differential receiver cancels it because it looks only at the difference. Transceivers still have an input range, about −2 V to +7 V.
Controller and transceiver
The controller is the digital block (or chip) that builds and checks frames. The transceiver turns its logic levels into the differential voltages on the bus and back.
CRC (cyclic redundancy check)
A 15-bit remainder of the frame bits divided by a fixed polynomial. The receiver repeats the calculation and signals an error if the results differ.
CRC error
The received CRC does not match the one the receiver calculated. The receiver does not acknowledge and sends an error flag after the ACK delimiter.
Data frame
The normal frame that carries 0 to 8 bytes of data. A remote frame (rarely used) has no data and asks for the message with that identifier.
Differential signalling
Sending a bit as the difference between two wires instead of the voltage on one wire. It rejects noise common to both wires.
DLC (data length code)
Four bits that say how many data bytes follow. Values 9 to 15 also mean 8 bytes in classical CAN.
Dominant
The state a node drives actively, logic 0. If any node drives dominant the bus is dominant.
ECU (electronic control unit)
A small computer in a vehicle, such as the engine controller or a door module. On CAN it is a node.
EOF (end of frame)
Seven recessive bits that finish a frame. Together with the three-bit gap (IFS) it makes the 13-bit tail that is not stuffed.
Error frame (error flag)
A burst that a node sends when it detects an error. It breaks the stuffing rule on purpose so that every node sees the error and discards the frame.
Error-active and error-passive
The two states below bus-off. An error-active node signals errors with six dominant bits. A node with a transmit counter of 128 or more is error-passive: its error flag is recessive and it must wait an extra 8 bit times before it sends again.
Extended frame
A frame with a 29-bit identifier (CAN 2.0B), sent as an 11-bit base ID and an 18-bit extension. A standard frame has 11 bits (CAN 2.0A).
Form error
A fixed-form bit (a delimiter, or the EOF) has the wrong value.
Gateway
A node that connects two buses and passes selected messages between them. Real vehicles often put different sensors on different buses behind a gateway.
Identifier (ID)
The number in the arbitration field. It names what the message is (for example engine speed), not who it is for, and its value sets the priority: lower wins.
IFS (interframe space)
Three recessive bits between frames. The simulator counts them as part of a frame’s length.
Jitter
A variation in when a message becomes ready to send. The response-time calculation adds the jitter J to the wait.
Mailbox (transmit buffer)
The place where a controller holds a frame to be sent. In Step 3 each sensor has one, so a new sample replaces an unsent older one, which is counted as lost.
Message-based
Frames carry an identifier for their content instead of a destination address. Any node can listen to any message.
Multi-master
Any node may start sending when the bus is idle. There is no central controller.
Node
Any device connected to the bus: a controller with a transceiver and the ECU behind them.
Non-destructive arbitration
The losing node stops without damaging the winning frame, so no bandwidth is lost to the collision.
OBD-II
The diagnostic connector under a car dashboard. Most cars carry CAN on its pins 6 and 14.
Phase segments
The two parts of the bit after the propagation segment. The receiver samples between them and lengthens or shortens them to stay in step with edges.
Priority
Set by the identifier: the lower the number, the higher the priority. It decides who wins arbitration and so who waits.
Propagation segment
The part of the bit that allows the signal to cross the bus and come back, plus the transceiver delays.
Quantisation
Rounding a value to a whole number of scale steps so that it fits in the data bytes. The largest error is half a step.
Recessive
The state of the bus when no node drives it, logic 1.
Response time
The time from a message becoming ready to its last bit arriving. It includes blocking, waiting for higher-priority frames and the frame’s own length.
Resynchronisation
A receiver moves its sample point a little when an edge arrives earlier or later than expected, which absorbs small differences between nodes’ oscillators.
RTR and SRR
RTR (remote transmission request) is dominant in a data frame and recessive in a remote frame. SRR (substitute remote request) takes its place in an extended frame and is always recessive.
Sample point
The moment inside a bit when the receiver reads the bus, as a share of the bit time (commonly 75 to 87.5%).
SOF (start of frame)
The first bit of a frame, always dominant. It gives the other nodes an edge to synchronise on.
Stale
A value that is older than the allowed limit, here more than a chosen number of the sensor’s own periods. CAN gives no warning, so the receiver has to check the age.
Starvation
A low-priority message never gets the bus because higher-priority traffic keeps it busy. The lowest-priority messages go first.
Stuff error
Six equal bits in a row between the start of the frame and the CRC sequence. It signals an error.
TEC (transmit error counter)
The counter a node keeps of its own transmit errors: plus 8 for an error, minus 1 for a good frame. It sets the error-active, error-passive and bus-off states.
Termination
A 120 Ω resistor at each end of the bus. It matches the cable so that edges do not reflect. Two in parallel read about 60 Ω.
Twisted pair
Two wires wound around each other. Noise from outside reaches both wires almost equally, so it cancels in the difference the receiver reads, and the opposite currents in the two wires cancel each other’s radiated field.
Time quantum
The smallest unit of time in a bit, set by the node’s oscillator and prescaler. A bit has typically 8 to 25 of them.
Wired AND
A bus whose level is the AND of all the bits driven onto it: 0 if any node drives 0.

No term matches. Try a shorter word.

What each setting does

Each row says what happens when you raise the setting. The Step 3 numbers were measured by running the simulator’s own bus model on its default six sensors with 500 kbit/s, real stuffed lengths, the 16 s run, trouble from 4 s to 10 s and noise seed 7, changing one setting at a time. They are a guide to the direction and size of each effect, and will shift if you change other settings or the simulator is updated. Stale shares are the share of the whole 16 s run.

Common questions

Why does the lower identifier win?

The identifier is sent most significant bit first. At the first bit where two identifiers differ, the smaller number has a 0, which is dominant, and the larger number has a 1, which is recessive. The bus shows 0, so the larger one sees a mismatch and stops.

Is a CAN message addressed to a node?

No. The identifier says what the message is, and every node decides for itself whether it wants it (the acceptance filter). That is why a new node can be added without changing the others.

The transmitter saw a dominant ACK slot. Did the dashboard get the frame?

Not necessarily. A dominant ACK slot means that at least one node received the frame without detecting an error. It does not say which node, so the sender cannot tell whether the intended receiver got it.

Why does a frame get longer with some data?

Bit stuffing. The sender adds a bit after every five equal bits, so a payload of zeros or ones needs more stuff bits than alternating data. That is why the simulator can use the real stuffed length or the worst case.

Is a bus load below 100% safe?

No. Load is an average. If several messages become ready together they queue behind each other, and a frame in progress is never interrupted, so a low-priority message can wait for several frames. Step 3 shows this with the Sampling setting.

Why do coolant and fuel go stale first?

They have the lowest priority. When traffic with a middle priority fills the bus, higher-priority sensors still win every arbitration but coolant and fuel lose to it. The lowest-priority messages starve first.

Why does 5% noise barely matter and 30% empties the dashboard?

Each hit adds 8 to the sender’s error counter and each good frame takes off 1. Below about one hit in nine the counter drifts back to zero. Above it, the counter climbs through 128 (error-passive) and 255 (bus-off), and the node is silent until it restarts.

Why does a faster restart after bus-off keep the readings fresher, and is it better?

The node is back on the bus sooner, so fewer samples are lost. But it also sends more frames into a noisy bus, so there are more error frames (1,387 against 812 in the default 40% noise case). A real controller leaves the restart time to software, and a node that keeps disturbing the bus is better left off.

Why does the dashboard not warn me about an old value?

A classical CAN frame has no freshness field. The receiver sees a frame when one arrives and nothing when none does. The check has to be made in the application, by noting when each frame arrived, and sometimes with an alive counter or a checksum in the data.

A sample was replaced in the transmit buffer and never sent. Is that a bug?

No, it is a choice. With one buffer per message, a newer reading replaces an older unsent one. If every sample waited in a queue instead, an overloaded bus would deliver old readings later and later. For a sensor the newest value is almost always the one wanted.

Is the calculated worst-case delay a prediction?

It is a bound. It assumes every higher-priority message is released at the worst moment and that no noise hits. The run usually stays well below it (for coolant at 500 kbit/s, the bound is 0.84 ms and a healthy run stays under 0.12 ms). Noise can break the bound, which is why the table says it assumes none.

Why can a classical CAN frame carry only 8 data bytes?

It was designed for short control messages that must arrive quickly. A short frame also limits how long a high-priority message can be blocked. Large data has to be split into many frames by a higher-layer protocol. CAN FD carries up to 64 bytes.

The bus is dead. What do I check first?

With the power off, measure the resistance between CAN_H and CAN_L: about 60 Ω is right, 120 Ω means one terminator is missing and an open circuit means both are. With the power on, a node stuck dominant holds the bus away from the idle 2.5 V. A wrong bit rate on one node, or a short between the wires or to ground, are also common.

Further reading

Start with the two Texas Instruments application reports, which are free and short. The Davis et al. paper is the source of the worst-case delay analysis, and the standards are the authoritative source but are sold by ISO. The numbers in the simulators are illustrative. Check each publisher page for the final details.

  1. Corrigan, S. Introduction to the Controller Area Network (CAN). Texas Instruments application report SLOA101. ti.com/lit/SLOA101
    A readable walk through the frame, arbitration, error handling and the bus levels, with the same dominant and recessive picture used here.
  2. Corrigan, S. Controller Area Network Physical Layer Requirements. Texas Instruments application report SLLA270. ti.com/lit/slla270
    Termination, cable, stubs, bit timing and the relation between bus length and bit rate, which Step 1 simplifies.
  3. Di Natale, M., Zeng, H., Giusto, P. & Ghosal, A. Understanding and Using the Controller Area Network Communication Protocol: Theory and Practice. Springer (2012). springer.com
    A textbook on the protocol, bit timing, error confinement (including the counter rules Step 2 skips) and timing analysis.
  4. Davis, R. I., Burns, A., Bril, R. J. & Lukkien, J. J. Controller Area Network (CAN) schedulability analysis: Refuted, revisited and revised. Real-Time Systems 35, 239–272 (2007). doi:10.1007/s11241-007-9012-7
    Shows how arbitration and the worst-case frame length (including stuff bits) set how long a message can wait. Equation 13 and the worst-case table in Step 3 use this analysis.
  5. Bosch. CAN Specification, Version 2.0 (1991).
    The original specification of the classical frame (parts A and B). Search the title to find a copy.
  6. ISO 11898-1 (data link layer) and ISO 11898-2 (high-speed physical layer).
    The international standards that define the frame and the bus levels used in these pages. Search the standard numbers on the ISO website.
