How does a message win the bus?

In Step 1 the bus was a shared wired AND: if anyone is dominant, the bus is dominant. Now follow one message from a few numbers to bits on the wire. You choose its identifier and data, lay out the frame, compute its CRC, stuff its bits, make it compete against two other nodes for the bus, and finally see what the bus does when something goes wrong. Everything on this page is computed live from the model, so change the message in step 1 and every later step follows.

After this page you can

  • lay out a frame from an identifier and data, name each field, and say where the CRC and the bit stuffing apply;
  • work out by hand how many bits, and how many microseconds, a frame takes once stuff bits are counted;
  • predict which node wins arbitration and at which bit the others drop out, and say what the ACK slot and the error counters do and do not tell you.

    Check yourself

    Why does the lower identifier win arbitration?

    Identifiers are sent most significant bit first and every node reads the bus while it sends. At the first bit where two identifiers differ, the smaller number has a 0 (dominant) and the larger has a 1 (recessive). The bus becomes 0, so the node that sent 1 sees a mismatch, stops, and becomes a receiver. The node that sent 0 saw exactly what it sent and carries on.

    The loser of arbitration was sending its frame too. Is anything corrupted or lost?

    No. The winner’s bits are unchanged, because the loser sent a recessive bit that the dominant bit simply overrode, and the loser then went quiet. The loser still has its message queued and tries again as soon as the bus is free, so the only cost is waiting. That is why CAN calls arbitration non-destructive.

    Two nodes send the same identifier at the same time. What happens?

    Neither ever sees a mismatch during arbitration, so both carry on into the control and data fields. If their data differs, one sends a 1 where the other sends a 0, and the node that sent the 1 reads a 0 outside arbitration: a bit error. The frames collide and both nodes raise error frames. This is why every identifier must be sent by one node only. Try it in step 5 by giving two nodes the same ID.

    Is the CRC calculated before or after bit stuffing, and does it cover the stuff bits?

    Before. The CRC is computed over the original bits from the start of frame to the end of the data field. Stuff bits are added afterwards, to everything from the start of frame through the CRC sequence, and removed by the receiver before it checks the CRC. Stuff bits are not part of the CRC. Step 4 shows the receiver recovering the original bits.

    The transmitter reads a dominant ACK slot. What exactly does that tell it?

    Only that at least one node received the frame without detecting an error. It does not say which node, or that the intended consumer got it, or that every node did. In step 6 receiver B hears corrupted data and refuses to acknowledge, but the transmitter still sees a dominant ACK slot because receiver C acknowledged. The error flag that B sends afterwards is what makes everyone discard the frame.

    A node’s transmit error counter goes up by 8 on a failed send and down by 1 on a good one. What does that mean for a node that fails one frame in ten?

    Ten sends give +8 for the failure and −9 for the nine successes, so the counter stays near zero: occasional errors are tolerated. A node that fails more than about one frame in nine climbs steadily, goes error-passive at 128 and bus-off above 255. The rule separates a noisy moment from a broken node and takes a node that keeps disturbing the bus off it. Step 6 lets you watch it happen.

    A standard frame and an extended frame have the same 11 leading identifier bits. Which one wins?

    The standard frame. After the 11 base ID bits, the standard frame sends RTR (dominant for a data frame) while the extended frame sends SRR, which is always recessive. The standard frame’s dominant bit wins. In general arbitration covers the whole arbitration field, which includes those control bits.

    In three lines

    1. A frame is fixed fields in a fixed order, so a receiver knows what each bit means from its position alone; the CRC covers everything from SOF to the last data bit.
    2. Stuff bits make the length depend on the data (8n + 47 bits at best for a standard frame, about a quarter more at worst), which is why the timing analysis in Step 3 uses the worst case.
    3. Arbitration compares identifiers bit by bit and the lower number wins without damaging the frame; the ACK slot says only that someone received it, and the error counters (+8, −1) tolerate rare faults but shut down a node that fails more than about one frame in nine.
