ReRAM Crossbar Simulator

A crossbar is a grid of ReRAM cells. Each word line (a row) carries an input voltage, each bit line (a column) collects current, and a cell sits at every crossing with its stored conductance G.

Weights are stored as conductances in a resistive-RAM crossbar. Input voltages on the word lines produce bit-line currents that already equal the matrix product, Iⱼ = Σᵢ Vᵢ·Gᵢⱼ, so the multiply and the sum both happen inside the array.

This is a generic, textbook model of analog ReRAM compute-in-memory: a passive crossbar with differential conductance pairs, a quantized DAC and ADC, Gaussian device variation, wire IR drop and a pulse-and-verify model of how the weights are written. It is meant for learning and quick experiments, not as a novel architecture or a model of any specific chip.

Path through this page: 1) Warm-up: one cell, then two on a wire. 2) A 2×2 multiply, number by number. 3) The full crossbar. 4) How negative weights are stored. 5) Writing the weights and what it costs. 6) Efficiency against a digital multiply-accumulate. Extensions at the end are optional. Here a weight is simply a number that scales an input, and a vector-matrix multiply is a set of multiply-and-add sums done together.

Warm-up: one cell, then two cells on one wire start here

To read its stored value, a ReRAM cell acts like a resistor whose size you set when you program it. The only law you need is I = V × G: the current I equals the voltage V across the cell times its conductance G (the opposite of resistance). Think of water in a pipe: V is the pressure, G is how wide the pipe is, and I is how much water flows. Drag the sliders, then put a second cell on the same wire.

A crossbar column is this picture repeated: many cells share one bit line, each cell turns its row voltage into a current, and the wire adds them up. The conductance range of the sliders follows Gmin and Gmax in the Device and circuit panel.

Worked example: a real 2×2 vector multiply follow every number

Here the crossbar computes y = xᵀW for a 2-element input vector and a 2×2 weight matrix. The inputs from the vector x become voltages on the rows. The weights from the matrix W become conductances in the cells, two cells per weight (G⁺ and G⁻) because a conductance cannot be negative. Each column adds up its currents, and the result is compared with the exact answer. Inside each cell box the big number is its conductance and the small one is its current; tap a cell to see where they come from. Change any number, and use the Device and circuit settings beside the crossbar (DAC and weight bits, ADC bits, Gmin, Gmax, σ, wire resistance) to see where the differences come from. This example uses the analog multi-level layout. The Cell layout menu compares the default two-cell pair with two single-cell alternatives.

Negative weights: signed or unsigned, one cell or two? read when you reach negative weights

A ReRAM cell is a conductance G, and G can never be negative, so a current I = V·G can never be negative either. A weight is the number that scales an input, and weights are often negative as well as positive. Two separate design choices decide how the array copes, and you can set each one with the drop-downs above.

1. Weight sign: are negative weights needed?
Signed keeps them, so the output can go below zero. Unsigned gives up on them: a negative weight is stored as 0. That is fine when every weight is naturally positive (pixel intensities, counts, probabilities), and wrong when it is not.
2. Cells per weight: how is a signed weight stored?
G⁺/G⁻ pair uses two cells: one holds the positive part, one the negative part, and the column pair’s currents are subtracted. G⁺ only uses one cell. To keep negatives anyway it shifts the weight into 0 to 1 and subtracts a shared reference column that stands for zero.

L is the number of conductance levels minus one (set by “Weight levels”) and ΔG = Gmax − Gmin. The fourth combination, unsigned with a pair, is not offered: G⁻ would stay at Gmin and the second cell would buy nothing.

Why not always use the pair? It is the most accurate way to keep negatives, but it doubles the cells, the bit lines and the ADCs. If area or energy is tight, one cell per weight is attractive.
Why does the reference column halve the resolution? One cell has to cover weights from −1 to +1, so the same conductance range is spread over twice the span. Each level now means a change of 2/L in w instead of 1/L.
What does unsigned really cost? Negative weights turn into 0 and the leakage current of every cell piles up in the sum. The error is large when many weights are negative and small when none are.

Try it. (1) Press Randomize with Signed, pair, note y₁, then switch to Unsigned: negative weights turn red and y₁ moves. (2) Press “Make weights positive” and the unsigned result now differs from ideal only by the leakage offset. (3) Set σ = 0 and the ADC to 8 bits, then compare Signed, pair and Signed, G⁺ only: the same ideal answer, but the second is coarser when Weight levels is small. (4) Combine with Binary weighted cells to see the same three layouts at bit level.

Writing the weights into the array

Before any multiply, each weight has to be written as a conductance. The controller first erases the array to the high-resistance state, then nudges each cell with SET pulses (raise G) and RESET pulses (lower G), reading it back after every pulse and stopping when it is within tolerance of its target. The conductances this produces are the ones the crossbar above computes with. The device model is a simple illustrative one, so adjust it to explore the trade-offs.

The crossbar keeps the weights where they are and finishes all of them in a single read. Example 1: which side of the picture is lit? tiny example

Pick a 2×2 picture (4 pixels) or a 3×3 patch (9 pixels). The array stores four templates: Left, Right, Top and Bottom. Each template is a column of weights: +1 for “I want this pixel lit”, −1 for “I want it dark”, and 0 for “I don’t care” (3×3 only). The picture goes in as voltages, every cell adds its current to its bit line, and the template that overlaps the picture most collects the most current. In the 3×3 case the templates are edge-detecting kernels like those used in image processing, so this is one step of a convolution. It is a one-layer neural network (a weighted sum per template, then pick the biggest), computed in a single read.

Example 2: how does a weight get written into a cell? step by step

A ReRAM cell can’t be set to an exact value with one pulse, because every device responds a little differently. So each weight is written with a short loop: pulse, read the cell back, compare with the target, and repeat until it is close enough. Tap any number in the matrix (it is the matrix currently in the simulator, so load the example above to see its templates) and step through how it is stored in a pair of cells. SET and RESET are opposite-polarity pulses applied across the cell; Step 1 shows what each does to the filament and where the pulse is injected.

Example 3: why XOR needs two crossbars

XOR is 1 when exactly one of the two inputs is on. One crossbar can only draw a single straight line through the four cases, and no line separates XOR’s 0s from its 1s. With two crossbars and a comparator in between it works: A asks “is any input on?” (h₁) and “are both on?” (h₂), and B answers “any, but not both”.
